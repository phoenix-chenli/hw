# 云端分析 v1 契约

本契约为本机单用户 A 交付。`local-user` 仍由服务端注入；这不是 C 的生产登录或多人授权。四个原项目保持独立，旧 `local-tools-v1` 不变。

## 请求与运行

`GET /api/agent-runs/config` 返回来源、配置是否齐备、固定安全说明、运行时名称、人工版本标签和剩余派发尝试次数。没有地址或密钥。`configured=true` 只代表配置齐备，不代表平台连通性经过验证。

`POST /api/agent-runs`：

```json
{
  "operationId": "本次操作唯一标识",
  "expectedRevision": 0,
  "projectId": "已有项目ID",
  "request": {
    "intent": "research",
    "question": "这些资料能支持什么，仍缺什么？",
    "sourceIds": ["本项目资料ID"]
  },
  "authorizeCloud": false
}
```

问题最多 2,000 字符，资料为 1–6 份且不得重复，总计最多 20,000 UTF-16 代码单元。仅研究分析意图可执行，其他已保留意图返回未启用错误。

快照由后端从当前资料生成；不接受客户端提供的快照、provider、结果、身份或状态。配置未齐时保存为 `blocked`，没有传输；配置齐备时必须本次明确授权。旧操作回执先重放，不因配置改变追认授权。不同内容使用同一操作标识仍返回冲突。

运行状态：

```text
queued → running → proposal → accepted
                 → needs_input
                 → failed
                 → interrupted
       → blocked
       → interrupted
```

终态不自动重跑。显式重新提交产生新运行和当前资料快照。服务重启把留存的 queued/running 标记 interrupted，不重新发送。待派发时资料已经更新也不发送旧快照。

一个本机服务同时派发一份请求。派发前先原子保存 invocation，累计计数包含失败、中断与超时；次数按工作区来源累计，重启不清零。持久化失败时停止派发并要求恢复存储后重启。阶段 A 的次数上限不是平台金额预算。

`POST /api/agent-runs/interrupt` 输入 `{projectId,runId}`，只停止本地等待；终态重复操作不改变历史。不能承诺平台停止执行或停止收费。

## 固定证据快照

`xingjian.run-snapshot.v1` 包含项目、资料版本/标题/类型/内容哈希、连续片段和上下文哈希。内容哈希是原文 UTF-16LE 字节的 SHA-256，明确覆盖每个原始代码单元；上下文哈希绑定规范构建的完整快照。

每个证据片段包含本次运行内的 `ev-N`、资料与版本、原文哈希、UTF-16 半开区间、真实保存文本行范围、原文和定位描述。分块最多 1200 个代码单元，避免切开有效代理对；不规范化换行，不默默删去原文。读取历史时按保留版本重建核对，而不是用当前版重算。

授权留痕绑定该快照哈希、是否同意发送及同意时间。调用记录区分本机生成的请求/会话标识与实际响应提供的平台标识；人工版本标签不冒充平台返回版本。运行说明与错误只接受安全固定文案。

## 提案与确认

提案结构为 `xingjian.analysis-proposal.v1`，严格字段为 decision、summary、claims、tasks、gaps、questions 和 schemaVersion。候选结论最多 12 条，每条最多 8 个已有证据编号；建议任务最多 12 条，依赖只能指向本次候选。需要补充信息时必须给出问题，不能同时输出结论/任务。允许仅说明资料缺口。

模型不能填用户身份、项目身份、原始坐标、版本或任意附加字段。编号、位置和原文核查只证明引用对应，不自动证明语义支持或完成了计算。模型返回不执行脚本、公式、SQL 或资料内指令。

`POST /api/commands` 的 `accept_agent_run` 使用原有 operationId/expectedRevision 事务回执机制，payload：

```json
{
  "projectId": "已有项目ID",
  "runId": "运行ID",
  "claimIds": ["c1"],
  "taskIds": ["t1"],
  "acknowledgeEvidence": true
}
```

确认时要求有效 proposal、最新资料、非空选择、任务的候选依赖同时选中和主动原文核对确认。成功后仅添加所选结论/行动，保存映射回执，原提案不变；重复确认不重复创建。后续人工复核的版本不回写已接受原始候选。

通用 HTTP 命令入口不允许 create_agent_run；运行生命周期转换也没有公开命令入口。运行只能由管理器生成快照并写入状态；客户端无法提交伪造完成记录。

## 数据及失败边界

`project.agentRuns` 为可选字段，每项目最多 40 次。旧工作区仍合法，旧分析算法和验证规则不被替换。读取运行记录时验证严格字段、生命周期、时间、完整快照、引用及原始确认内容；不重新调用模型。这是本地完整性检查，不是加密签名。

默认关闭、配置不齐、限额、需要补充信息、无效提案、运行失败与中断分别呈现。网络响应丢失或回执无法读取时保留操作标识；过期写入刷新后保留输入和勾选，必须按当前资料重新分析。未提交输入不保证跨刷新恢复，已保存运行记录仍在本地。

本轮使用当前官方 InvokeRuntime 的 JSON/SSE 事件与本项目唯一结束结果约定，具体搭建、配置和仍未执行的真实验收见 `AGENTARTS-WORKFLOW.md`。没有自动真实调用、公开部署或模拟结果冒充平台接通。
