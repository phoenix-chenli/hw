# 行简研学实施路线

以 2026-10-24 新仓第一阶段为本仓编号起点。原 Word 中的 P0/P1/P2 是技术依赖拆分，不能按同一序号当作已经验收。当前第一阶段、第二阶段本地部分、第三阶段 A 逐项复核及 B 任务推进已实现；用户已确认「尚未开通，先完成本地部分」。真实平台与排版技术验证仍未完成。

## 第一阶段：独立基础与关系验证

建立独立私有仓、锁定四仓来源；实现统一对象、可操作 Web 工作台、本地保存、来源更新预览与确认；建立自动检查。证明同一资料、结论、行动和草稿可以建立可靠关系。

范围：手工输入、显式关联、单用户本机。不得把 mock、UI 或纯规则引擎说成真实 AgentArts。

## 第二阶段：真实平台与分析最小链路

**当前状态：本地部分已实现；云端部分待开通。** 已新增关键词检索、严格 CSV 聚合、版本化分析记录、选择确认与过期拦截，详见 `PHASE-02.md`。这些是遵循知衡证据边界的新实现，不是知衡完整检索引擎或 AgentArts 的真实接通。后续可先进行第三阶段的本地核查流程；AgentArts 正式接通仍是参赛必要待办，不能被本地工具替代。

1. 核实团队 AgentArts 账号、可用模型、调用预算与网络环境，密钥仅保存在服务端。
2. 先用一条只读工具验证 AgentArts 实际构建、编排、调用和运行记录。不把本机 localhost 当作平台可访问服务。
3. 将知衡检索/受控计算适配为窄接口，返回项目、来源版本、定位精度、结论和缺口。缺定位保持未知，不编造页码。
4. 平台输出先展示为提案；用户确认后转换为本仓对象。来源版本变化时拒绝直接入库。
5. 在增加公网访问之前完成真实身份、项目授权、工具鉴权、限额和持久存储迁移。模型参数不能决定用户身份。
6. 验收：真实调用日志对应界面结果，资料不足与工具失败分支可重现。未获模型调用预算时，只做不调用模型的契约测试。

## 第三阶段：核查与任务推进

**第三阶段 A：逐项复核已实现。** 对照新旧资料与关联结论，分别确认结论、行动和草稿；记录复核说明、内容版本和当时依据。资料再次变化会重新提醒；复核不改变任务完成进度，不一键抹除下游提醒。界面、冲突恢复与验证范围见 `PHASE-03.md`。

**第三阶段 B：本地计划与继续点已实现。** 保存真实任务下一步、进展、阻碍和资料版本入口；录入具体日期的课程与忙碌时段，先预览再确认时间块。复用行简“先预览再确认”和知途“记录真实继续点”的边界，新写本地接口，没有迁入原服务。允许显式课内安排并保留提醒；计划覆盖同一用户跨项目占用，取消保留历史。详见 `PHASE-03B.md`。

已验证：重复确认不重复写、过期计划重新预览、关闭重开能回到真实继续点。计划与继续点不会自动完成任务；本阶段没有计时器或推送提醒。学期课表导入、自动调整建议、拖拽改期和个人日历接入尚未实现。

## 第四阶段：固定模板成果

先验证受限 ReportSpec → JATS 子集 → PDF；根据真实输出决定适配范围。排版环境放独立 worker，不在用户电脑安装原生 SDK 或整包编译环境。锁定来源和报告版本，保留缺口提示、编译失败原因和历史产物。

## 第五阶段：交互深化与研究小组试用

完善证据定位、差异查看、失败恢复、键盘和窄屏体验。找 3–5 个真实课程研究小组验证资料更新/导师反馈场景，记录再次使用、核对成本、漏项和返工。UI 迭代依据观察，不增加无用途仪表盘。

## 第六阶段：平台评测与参赛交付

用固定任务集对比普通工具组合、仅资料分析、完整流程。记录完成率、依据支持、计算正确性、约束违规、耗时和成本。完成真实部署、可复现演示、架构与材料。所有指标来自实际测试，不将四个原仓的历史测试数量相加。
