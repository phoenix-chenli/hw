# 外部能力与本地适配边界

本阶段新增的是共同对象与确定性变更追踪，不复制四仓运行目录，也没有加载旧密钥、历史会话或真实校园资料。下列名称是本项目待实现协议，不是声称华为官方已存在的 API。

第二阶段增加了 `local-tools-v1` 本地分析实现：关键词摘录、CSV 列聚合和版本化提案。其 `sourceRevisions`、`contextRevision`、定位精度和确认时版本校验，参考来源基线中知衡 `answer_contract.py` 的 `_location`/`evidence_graph` 与 `product_api.py` 的 `scope_current` 边界。没有复制这些文件、载入知衡服务、迁移向量模型或声称与 `answer.v6` 兼容。窄接口定义见 `phase-02-contract.md`。

| 适配对象  | 最小输入与结果                                       | 必须保留的边界                                                      |
| --------- | ---------------------------------------------------- | ------------------------------------------------------------------- |
| AgentArts | 服务端可信身份、项目范围、目标 → 结构化提案与运行 ID | 真实发布应用；密钥不下发；模型不能调用最终用户确认                  |
| 知衡      | 项目限定资料版本、问题 → 依据定位/受控计算/结论/缺口 | 保留 source_revisions 与 context_revision；未知定位不补造；表格只读 |
| 行简      | 已确认工作项、时间范围 → 计划预览与确认回执          | 提案和最终写入分开；确认时版本检查和幂等；课内重叠明确提醒          |
| 知途      | 统一任务 ID、用户进展 → 继续点与作品关联             | 不迁移浏览器随机令牌为团队身份；时长不等于完成；记忆需同意          |
| JATSCraft | 受限版本化 ReportSpec → JATS 子集 → 独立排版任务     | 不直接把 JSON 填入 DocumentIR；固定模板；源版本与产物版本可追溯     |

前端实际接口见 `phase-01-contract.md`。本地身份 `local-user` 只用于单用户本机，后续必须通过真实身份上下文替换。不要通过删除 Host/Origin 限制将基础服务暴露公网。
