# 第二阶段本地分析契约

## 范围与来源

这是本仓新实现的 `local-tools-v1`，不是 AgentArts API、知衡 `answer.v6` 或模型适配器。依据：来源基线固定提交的知衡 `answer_contract.py` 中 `_location` / `evidence_graph`、`product_api.py` 中 `scope_current`。借鉴的是来源版本、定位精度、计算/结论关系及过期拒绝的语义约束，没有复制上游实现或载入其服务。

分析结果不可信为“已验证结论”；摘录只证明原文存在，数值结果只证明按输入执行了限定运算。全部文字始终作为数据处理，不执行其中指令、公式或 SQL。

## HTTP 与身份

沿用第一阶段的仅本机、单用户边界：服务端注入 `local-user`，Host / Origin / 客户端标识限制不变。前端或未来模型参数不得决定用户身份。所有写入仍使用 `POST /api/commands`，必须带 `operationId`、`expectedRevision`；表体上限 256 KiB。

`POST /api/analysis/catalog`：输入 `{projectId, sourceId}`，只读当前资料版本，输出 `{sourceId, versionId, rowCount, columns:[{name, invalidRows}]}`。`invalidRows` 是粘贴文本中的物理行号，不是原始 Excel 行号。错误不会写入状态。

`GET /api/capabilities` 明确返回 `stage:2`、`sourceAnalysis:"local-keyword-and-csv"`、`analysisProvider:"local-tools-v1"`、`agentArts:"not-connected"`。

## 写入操作

### run_analysis

```json
{
  "projectId": "已有项目ID",
  "request": {
    "mode": "search",
    "sourceIds": ["同项目资料ID"],
    "query": "用电 采样"
  }
}
```

计算模式：

```json
{
  "projectId": "已有项目ID",
  "request": {
    "mode": "calculate",
    "sourceIds": ["单份CSV资料ID"],
    "column": "日用电量(kWh)",
    "operation": "sum"
  }
}
```

服务端根据当前资料生成提案，不接受客户端提交的候选正文。结果只追加到 `project.analyses`，不会创建结论、任务或草稿。回执 `entityId` 为分析 ID。

`AnalysisRun` 保留：运行 ID、创建时间、规范化请求、`sourceRevisions`、`contextRevision`、输出、`pending|accepted` 状态、确认回执。`contextRevision` 是项目 ID 与所选资料版本列表的 SHA-256 标识，不是原文件内容哈希或华为平台运行 ID。

输出包括候选结论、建议任务、限制/缺口与本地工具执行记录。每个候选都有明确来源版本；摘录保留 `quote` 和 UTF-16 `[start,end)` 偏移、粘贴文本行号；计算保留列名、行范围、运算、结果、样本行数及舍入标记。不生成原始文件页码。

### accept_analysis

```json
{
  "projectId": "已有项目ID",
  "analysisId": "服务端保存的分析ID",
  "claimIds": ["claim-1"],
  "taskIds": ["task-review"]
}
```

这些 ID 是该提案内部的候选 ID。服务端验证：项目所属、记录存在、尚未确认、所选资料版本仍当前、选择非空、所有选择有效、关联行动所依赖的候选必须一起选中。确认原子地创建新对象并保存候选→实际对象回执，不接受客户端替换正文。

一次提案确认后关闭，未选内容不会补写。需要不同选择可重新分析。已确认对象之后仍受资料更新的复核提醒保护。无匹配时可以仅添加无结论依赖的“补充资料”任务，不能凭空添加结论。

相同 operationId 的同一操作重试返回原回执；不同 operationId 再次确认同一提案返回 `ALREADY_ACCEPTED`，不会重复写入。任何被选资料更新均触发 `ANALYSIS_STALE`，即使浏览器已刷新工作区修订号也不能绕过。无关资料变更不使该提案的来源快照过期。

## 算法与容量

- 单次 1–10 份资料、总计不超过 300,000 字符；计算模式限定一份资料。每项目最多 100 份分析，仍受 24 MiB 工作区容量约束。
- 关键词用空格/逗号/分号分隔，最多 8 个、每个最多 64 字，请求最多 300 字。按字面、不区分大小写匹配，正则特殊字符转义；按命中关键词数排序，最多展示 6 行。命中数量不是可信度，没找到不等于资料无答案。
- CSV 首行表头，最多 40 列、5,000 行数据；支持标准双引号、引号内逗号/换行、CRLF。只跳过全空白物理行，含分隔符或引号的空记录保留并校验。列名重复/空白、列数不齐、引号未闭合直接失败。不会猜分隔符、跳过说明文字或自动修复。
- 数值需为普通十进制：最多 9 位整数、6 位小数，可带正负号。空值、科学计数、百分号、公式、千位分隔、非有限值、混入单位拒绝，不静默过滤。BigInt 定点运算避免二进制浮点累加误差；平均值舍入至 6 位小数，半数远离零，记录是否发生舍入。
- 运算限定 `sum/mean/min/max/count`，`count` 统计完整有效数值列的个数。单位只保留列名，不推断、不换算、不进行因果或显著性判断。

## 失败与持久化

400：参数、CSV、数值列或选择错误；404：对象不存在/不属于项目；409：全局修订冲突、来源过期或已确认。数据校验/工具失败发生在提交之前，状态和回执不改变，界面保留输入。当前失败原因在接口及页面显示，不宣称已有持久化失败轨迹或云端追踪。

旧工作区没有 `analyses` 时视为没有分析记录，不重置旧数据或提高 schemaVersion。已有分析在读盘和写入时按保留的历史资料版本重算校验，以防记录/候选损坏。后续算法升级需保留旧引擎或明确迁移，不能改算法后直接拒绝所有旧记录。此机制不等同于密码学签名或防恶意本地篡改。

前端用 sessionStorage 保存本标签页的项目 ID 与页面名；存储不可用时仍能工作。提案输入在当前页面保留，未提交的草稿不保证跨页面/刷新恢复；业务数据和分析历史由服务端持久保存。

## 后续云端接入必须补齐

平台开通与真实应用发布、正式调用协议/鉴权、可信身份与项目授权、公网可达且受控的只读工具、超时/限额、密钥保护、平台运行 ID 和实际调用证据。当前没有模型或云端网络请求，也不能把本机接口直接交给平台当公网服务。
