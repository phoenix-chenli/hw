# 行简 · 研学工作台

面向华为 ICT 创新赛赛题 2「基于华为云 AgentArts 智能体开发平台的 Agent 设计和应用」的独立工程。

帮助课程研究与大创项目把**资料版本 → 结论依据 → 后续行动 → 成果草稿**关联起来。资料变化时，先看影响，再确认保存，保留历史与原有工作进度。

**当前交付：第三阶段 B，任务继续点与本地计划预览，单用户工作台。** 已支持关键词依据检索、CSV 受控计算、提案选择与确认、逐项复核，以及任务继续点、课程/忙碌时段录入和时间安排确认。本地工具参考四仓的资料、确认与进度边界重新实现窄接口，未迁入原项目完整引擎；AgentArts、云模型及 JATS 排版尚未接入。用户已确认暂不开通云端，本轮没有模型调用或费用。

## 运行

需要 Node.js 22.14 或更新版本。无需 DevEco、HarmonyOS SDK、Android/iOS 环境、Python 或模型密钥。

```sh
npm ci
npm run build
npm start
```

访问 **http://127.0.0.1:8787**。所有业务内容保存在本机 `.runtime/workspace.json`，不会上传至 GitHub。服务固定监听 `127.0.0.1`；当前没有生产账户体系，不能直接开放公网。

开发页面：`npm run dev`，访问 http://127.0.0.1:5173。命令跨 macOS / Windows / Linux，脚本不依赖 Bash 语法。

可复制 `.env.example` 为 `.env` 自定义本地配置。`XINGJIAN_DATA_FILE` 可指定独立数据文件。生产静态预览可用 `XINGJIAN_PORT` 改端口；开发前端代理默认仍连接 8787。

## 用两分钟体验核心价值

1. 首次打开时，选择「体验一个示例」。这是明确标注的合成校园节能研究，另有一条无关的资料室开放时间关联链。
2. 在「资料与依据」打开用电记录，选择「更新资料」，修改内容。
3. 点击「预览变更影响」：查看会受影响的结论、行动和成果草稿。此时尚未写入。
4. 点击「确认保存新版本」：仅已关联的内容变为待复核。任务进度、旧资料、原始引用和草稿文字保留；无关资料不受影响。
5. 点击「开始逐项复核」或各项「逐项复核」，先对照新旧资料，修改或保留结论，填写复核说明，再确认本项。
6. 分别核对行动和草稿：关联结论尚未处理时会提示先处理结论；任务完成进度不会改变。确认后可在「复核记录」查看旧内容及当时使用的依据。
7. 刷新页面，查看仍在的内容和历史版本。也可建立自己的项目，手工录入资料、结论、行动和草稿。

「已关联依据」只代表记录了出处；「已人工复核」记录用户确认，不保证结论正确。资料变化只沿已有关系追踪，不自动发现所有语义影响。复核每次只解除当前一项提醒，不会一键清空任务和草稿的提醒。旧数据没有记录的历史关联版本仍显示未知，不反推补写。

## 体验本地分析

1. 在「资料与依据」添加资料。关键词检索支持所有粘贴文本；计算请单独粘贴标准 CSV，例如下面的合成数据，标题注明「合成样本」。第一阶段示例的用电摘录含前后说明文字，不是纯 CSV，不能直接用于计算。
2. 打开「资料分析」→「表格计算」，选择数值列与合计/平均等运算，生成提案。或在「查找依据」输入空格分隔的关键词。
3. 检查摘录位置、来源版本、计算过程及限制。勾选需要的候选和行动，再点「确认加入所选内容」。未勾选的不写入。
4. 更新被分析的资料后，旧提案不能直接确认；点击「按当前版本重新分析」。已确认结论和任务继续受第一阶段的变更提醒保护。
5. 历史分析可重新打开；刷新保留当前项目与页面。浏览器只保存导航 ID，业务数据仍在本地服务。

```csv
教室,日用电量(kWh)
A教室,60
B教室,45
```

关键词检索只是字面匹配，不是语义问答；合计 105 只适用于这两行合成数据，不能用来论证节能效果。表格遇到空值、公式、百分号、混入单位等会拒绝计算，不静默跳过。详细限制见 [第二阶段本地交付](docs/PHASE-02.md)。

## 接着推进真实任务

1. 「行动清单」→「记录继续点」：记录这次做到哪里、下次第一步、当前阻碍，可关联一份资料的具体版本。下次打开会恢复最新留存，历史可回看。
2. 同页「安排专注时间」中，按需展开「上课与忙碌时间」，录入具体日期的课程或其他占用。
3. 选择日期、时间范围和行动时长，点「预览时间安排」。按所选顺序查找连续空闲，同一用户各项目中已录入的占用和已确认计划都会参与避让。已完成、待复核或放不下的行动会说明原因。
4. 默认避开上课。你可以勾选「允许安排在上课期间」；若实际重叠，核对课程提醒后还需单独确认。
5. 「确认保存安排」后保留具体时间块。资料/行动/继续点变化会提醒核对；新增时间冲突不会自动重排。需要调整时取消原安排，再重新预览，旧计划与任务进度仍保留。

所有时间明确采用北京时间（Asia/Shanghai），只按用户录入内容判断；没有自动读取课表、连接个人日历或推送通知。记录时间和生成安排均不代表任务完成。详细边界见 [任务推进交付](docs/PHASE-03B.md)。

## 数据与故障恢复

- 写入使用版本检查、持久幂等回执和原子文件替换。两个页面同时更改时，旧页面必须刷新并重新预览；失败不会静默覆盖新状态。
- 数据格式损坏时停止读取，不自动清空。先备份 `.runtime` 再检查，不要用示例覆盖真实数据。
- 同一数据文件只允许一个服务。正常退出会移除 `.lock`；异常退出后，**确认所有旧服务已停止**，再仅删除 `workspace.json.lock` 后重启。不要删除 `workspace.json`。为避免双写竞态，服务不自动清理旧锁。
- 当前为小规模本地工作区，数据文件上限 24 MiB、10,000 次写入回执。后续迁移数据库需要版本迁移与备份测试。
- `.runtime`、`.env`、用户资料和依赖目录被 Git 忽略。提供的是本地数据处理能力，不是多用户云服务。

## 工程结构

```text
src/                  React + TypeScript 白蓝工作台
shared/contracts.ts   项目、来源版本、结论、任务、草稿契约
server/domain.mjs     关系校验、影响预览、确认更新
server/analysis.mjs   本地只读检索/CSV 计算、提案与版本契约
server/review.mjs     逐项复核、内容版本与历史依据
server/planning.mjs   继续点、时间占用、计划预览与确认
server/store.mjs      原子持久化、版本冲突与幂等回执
server/http.mjs       仅本机 API 与静态页面服务
tests/                核心、接口、存储和浏览器回归
docs/                 范围、来源记录、后续接入路线
```

四个原项目保留独立历史与文件，本阶段没有向它们推送。来源版本和后续适配约束见 [来源基线](docs/source-baseline.json)；路线见 [后续阶段](docs/ROADMAP.md)。
