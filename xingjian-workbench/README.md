# 行简 · 研学工作台

面向华为 ICT 创新赛赛题 2「基于华为云 AgentArts 智能体开发平台的 Agent 设计和应用」的独立工程。

帮助课程研究与大创项目把**资料版本 → 结论依据 → 后续行动 → 成果草稿**关联起来。资料变化时，先看影响，再确认保存，保留历史与原有工作进度。

**当前交付：里程碑 A，云端分析协议、运行记录与证据校验；B 的首条 AgentArts 链路已完成调用准备，真实连通性待验证。** 本机单用户工作台仍支持原有检索、CSV 计算、逐项复核、证据定位、计划与报告。新增研究问题、固定资料快照、发送授权、持久运行状态、严格提案引用及选择确认；默认云端关闭，保存请求不发送资料。已按官方运行时接口准备受限调用适配与工作流搭建说明，本轮未配置真实应用或调用真实模型，没有模型调用费用。

平台工具检索/计算、多 Agent、生产登录、公网部署和完整 JATSCraft 尚未完成。四仓能力继续遵循来源与许可边界，当前是独立窄实现，不能将合成协议测试或配置齐备当作真实平台验收。

## 运行

需要 Node.js 22.14 或更新版本。无需 DevEco、HarmonyOS SDK、Android/iOS 环境、Python 或模型密钥。

```sh
npm ci
npm run build
npm start
```

访问 **http://127.0.0.1:8787**。业务内容保存在本机 `.runtime/workspace.json`，生成的 PDF 与任务状态默认位于 `.runtime/workspace.json.exports/`，不会上传至 GitHub。服务固定监听 `127.0.0.1`；当前没有生产账户体系，不能直接开放公网。

开发页面：`npm run dev`，访问 http://127.0.0.1:5173。命令跨 macOS / Windows / Linux，脚本不依赖 Bash 语法。

可复制 `.env.example` 为 `.env` 自定义本地配置。`XINGJIAN_DATA_FILE` 可指定独立数据文件。生产静态预览可用 `XINGJIAN_PORT` 改端口；开发前端代理默认仍连接 8787。

## 云端分析：先保存请求，再在配置齐备后明确授权

1. 打开「资料分析」，填写「本次研究问题」，选择 1–6 份资料，总计最多 20,000 字符（UTF-16 代码单元）。
2. 默认显示云端尚未启用。点击「保存分析请求」会保留问题和固定版本，标记「尚未发送」，不会向外传输资料。
3. 已有 AgentArts 账号、已发布工作流和批准的调用上限后，按 [平台配置与首次真实验收](docs/AGENTARTS-WORKFLOW.md) 只在服务端配置 `.env`。配置齐备仍显示待验证，打开页面不自动测试模型。
4. 主动同意发送本次选定资料后才能提交。结果先作为提案，逐条打开原文核对；选择行动会关联其候选结论，主动确认后才写入项目。
5. 需要补充信息、失败、中断、资料已更新各有独立提示。刷新记录不会重调模型；重启不会重发未完成请求。回执丢失/损坏时复用操作标识，过期提案须按当前资料重新提交。

当前只支持研究问题快照分析；变化建议、规划与草稿的云编排尚未开放，下方原有本地工具继续可用。引用校验只证明它对应留存原文，不证明结论被原文支持。每次派发先保守记入次数上限，不能等同于平台金额或实际计费次数。详情与实际截图见 [里程碑 A 交付](docs/MILESTONE-A.md)。

## 用两分钟体验核心价值

1. 首次打开时，选择「体验一个示例」。这是明确标注的合成校园节能研究，另有一条无关的资料室开放时间关联链。
2. 在「资料与依据」打开用电记录，选择「更新资料」，修改内容。
3. 点击「预览变更影响」：查看会受影响的结论、行动和成果草稿。此时尚未写入。
4. 点击「确认保存新版本」：仅已关联的内容变为待复核。任务进度、旧资料、原始引用和草稿文字保留；无关资料不受影响。
5. 点击「开始逐项复核」或各项「逐项复核」，先对照新旧资料，修改或保留结论，填写复核说明，再确认本项。
6. 分别核对行动和草稿：关联结论尚未处理时会提示先处理结论；任务完成进度不会改变。确认后可在「复核记录」查看旧内容及当时使用的依据。
7. 刷新页面，查看仍在的内容和历史版本。也可建立自己的项目，手工录入资料、结论、行动和草稿。

「已关联依据」只代表记录了出处；「已人工复核」记录用户确认，不保证结论正确。资料变化只沿已有关系追踪，不自动发现所有语义影响。复核每次只解除当前一项提醒，不会一键清空任务和草稿的提醒。旧数据没有记录的历史关联版本仍显示未知，不反推补写。

## 按清单逐项核对变化

1. 打开「项目首页」的「待复核清单」。只列出当前仍有提醒的内容，已完成任务若需复核也会显示真实完成进度。
2. 按结论、行动、草稿、当前关联资料和处理顺序筛选，或逐字查找标题/资料名称（不区分大小写）。筛选和分页不写入业务数据；切换项目会重置筛选。
3. 行动或草稿等待关联结论时，展开「查看需要先核对的结论」，选择具体结论，或打开本项查看依赖与原文。每项仍需核对填写并主动确认。
4. 保存后回到当前清单，数量、等待项和可先核对项按最新状态更新。取消会回到原按钮，保存使原入口消失时回到清单标题；不会自动打开下一项。
5. 「开始逐项复核」始终从完整清单的第一项开始，不受当前筛选影响。清单每页最多 8 项；全部处理后明确显示当前没有待复核内容。

「可先核对」只是本地导航顺序，保存仍以服务端最新版本和依赖校验为准。关联资料名称来自当前显式关系，不推断未知的历史版本。筛选文字和未提交复核输入不做跨刷新保存；真实完成状态与已保存复核历史仍在本机保留。详见 [第五阶段 B 交付](docs/PHASE-05B.md)。

## 原地核对证据与资料差异

1. 在分析提案、结论、行动、继续点、复核记录或报告中打开资料依据，原地查看当时引用的版本。查看后返回继续填写，复核说明和未确认的选择保留。
2. 能从显式分析候选或已接受结论映射验证原文与坐标时，高亮对应文本；CSV 计算显示实际记录占用的物理行范围。手工位置描述保持原样，无法可靠定位时明确说明，不猜页码或行号。
3. 在「在此版本查找」逐字搜索当前显示的资料，区分大小写。最多定位前 200 个匹配，超出时提示；正文每页 200 行，所有页面可继续查看。
4. 旧依据可显式切换至当前版本，也可对比引用版与当前版。原引用保持不变，旧版高亮不会套用到新版本；材料历史、更新预览和逐项复核也可查看文字差异。
5. 差异按新增、删除和行号展示，可逐处导航、展开上下文或切换完整原文。长文本超过精细匹配预算时明确改用整段展示，不裁掉原文；换行符和末尾换行变化也会提示。

高亮只说明找到了原文，不证明结论受该资料支持；当前行号对应保存的文本，不能等同于原文件页码。查看报告依据不改写报告内容和哈希。本阶段未开展真实研究小组试用，详见 [第五阶段 A 交付](docs/PHASE-05A.md)。

## 体验本地分析

1. 在「资料与依据」添加资料。关键词检索支持所有粘贴文本；计算请单独粘贴标准 CSV，例如下面的合成数据，标题注明「合成样本」。第一阶段示例的用电摘录含前后说明文字，不是纯 CSV，不能直接用于计算。
2. 打开「资料分析」→「表格计算」，选择数值列与合计/平均等运算，生成提案。或在「查找依据」输入空格分隔的关键词。
3. 检查摘录位置、来源版本、计算过程及限制。勾选需要的候选和行动，再点「确认加入所选内容」。未勾选的不写入。
4. 更新被分析的资料后，旧提案不能直接确认；点击「按当前版本重新分析」。已确认结论和任务继续受第一阶段的变更提醒保护。
5. 历史分析可重新打开；刷新保留当前项目与页面。已确认的业务数据仍在本地服务；部分未提交填写按下文暂存在当前浏览器标签页。

## 未保存填写的恢复

报告标题、章节选择与顺序、排期和时间占用，以及资料、结论、行动、草稿、复核和继续点弹窗的填写，会按项目和具体对象暂存在当前标签页。切换页面、误关弹窗或刷新后，再打开同一表单可恢复；保存成功后清理对应的临时填写。

恢复仅保留输入，不恢复旧预览、确认勾选或课内安排许可。报告、排期和资料变更仍需重新预览；复核重新读取当前依据，继续点核对最新进度。当前依据有更新时须再次核对，不会自动保存、覆盖历史或发起云端调用。

临时填写使用当前标签页的 sessionStorage，不上传 GitHub，也不作为长期备份。浏览器不允许暂存时，本窗口切页和误关仍可从内存恢复，但刷新后不保证保留；关闭标签页后也不保证恢复。

```csv
教室,日用电量(kWh)
A教室,60
B教室,45
```

关键词检索只是字面匹配，不是语义问答；合计 105 只适用于这两行合成数据，不能用来论证节能效果。表格遇到空值、公式、百分号、混入单位等会拒绝计算，不静默跳过。详细限制见 [第二阶段本地交付](docs/PHASE-02.md)。

## 接着推进真实任务

1. 「行动清单」→「记录继续点」：记录这次做到哪里、下次第一步、当前阻碍，可关联一份资料的具体版本。下次打开会恢复最新留存，历史可回看。
2. 同页「安排专注时间」中，按需展开「上课与忙碌时间」，录入具体日期的课程或其他占用。
3. 选择日期、时间范围和行动时长，点「预览时间安排」。按所选顺序查找连续空闲，同一用户各项目中已录入的占用和已确认计划都会参与避让。已完成、待复核或放不下的行动会说明原因。
4. 默认避开上课。你可以勾选「允许安排在上课期间」；若实际重叠，核对课程提醒后还需单独确认。
5. 「确认保存安排」后保留具体时间块。资料/行动/继续点变化会提醒核对；新增时间冲突不会自动重排。需要调整时取消原安排，再重新预览，旧计划与任务进度仍保留。

所有时间明确采用北京时间（Asia/Shanghai），只按用户录入内容判断；没有自动读取课表、连接个人日历或推送通知。记录时间和生成安排均不代表任务完成。详细边界见 [任务推进交付](docs/PHASE-03B.md)。

## 整理并下载进展报告

1. 打开「成果草稿」，在列表下方填写报告标题、选择草稿并调整章节顺序，按需包含关联行动。
2. 点击「预览报告」，核对实际引用版本、草稿/结论内容和待复核等提醒。提醒存在时须主动确认，再点「保存报告版本」。
3. 已保存版本可直接下载离线 HTML；点击「准备 PDF」，就绪后手动下载。页面重开仍可查询生成状态。技术详情内提供 JATS XML 和完整 JSON。
4. 资料或任务后续变化会显示提醒，旧报告保留当时内容；需要最新结果时重新预览，另存新版本。

每项目最多保留 30 份报告，每份最多 8 个草稿章节、60,000 字符。报告是研究进度草稿，不自动证明结论正确或满足投稿规范，也不解除复核提醒。详见 [第四阶段交付](docs/PHASE-04.md)。

HTML/JSON/XML 不需要浏览器。PDF 默认使用电脑上**已有的 Chrome**，独立 Node worker 生成，不自动安装浏览器或原生 SDK。没有 Chrome 时可先下载 HTML；已配置 Chromium 的 CI/worker 可设置 `XINGJIAN_PDF_BROWSER=chromium`。PDF 一次只生成一份，失败后可重试，不影响已保存报告。

## 数据与故障恢复

- 写入使用版本检查、持久幂等回执和原子文件替换。两个页面同时更改时，旧页面必须刷新并重新预览；失败不会静默覆盖新状态。
- 数据格式损坏时停止读取，不自动清空。先备份 `.runtime` 再检查，不要用示例覆盖真实数据。
- 同一数据文件只允许一个服务。正常退出会移除 `.lock`；异常退出后，**确认所有旧服务已停止**，再仅删除 `workspace.json.lock` 后重启。不要删除 `workspace.json`。为避免双写竞态，服务不自动清理旧锁。
- 当前为小规模本地工作区，数据文件上限 24 MiB、10,000 次写入回执。后续迁移数据库需要版本迁移与备份测试。
- 备份需要的 PDF 时同时保留数据文件旁的 `.exports` 目录。PDF 中断/缺失/校验失败会提供重新生成；报告快照仍在工作区。不要把真实报告或导出缓存提交 Git。
- `.runtime`、`.env`、用户资料和依赖目录被 Git 忽略。提供的是本地数据处理能力，不是多用户云服务。

## 工程结构

```text
src/                  React + TypeScript 白蓝工作台
shared/contracts.ts   项目、来源版本、结论、任务、草稿契约
shared/text-inspection.mjs  原始文本坐标、字面搜索与有界行差异
shared/evidence-location.mjs  只读验证已有引用的原文位置
shared/review-queue.mjs  从当前标记与显式关联派生待复核清单
shared/agent-contracts.ts  研究请求、固定证据快照、运行与严格提案协议
server/agent-protocol.mjs  历史原文/哈希校验、运行状态及人工确认
server/agent-runs.mjs  单并发、持久派发尝试计数、重启中断与错误恢复
server/agentarts-client.mjs  默认关闭的发布态运行时调用准备
server/domain.mjs     关系校验、影响预览、确认更新
server/analysis.mjs   本地只读检索/CSV 计算、提案与版本契约
server/review.mjs     逐项复核、内容版本与历史依据
server/planning.mjs   继续点、时间占用、计划预览与确认
server/reports.mjs    报告预览、不可变版本与历史依据校验
server/report-render.mjs 受限 JATS XML 解析与离线 HTML
server/pdf-jobs.mjs   本地 PDF 任务、缓存、校验和失败恢复
server/pdf-worker.mjs 独立进程使用已有浏览器打印 A4 PDF
server/store.mjs      原子持久化、版本冲突与幂等回执
server/http.mjs       仅本机 API 与静态页面服务
tests/                核心、接口、存储和浏览器回归
docs/                 范围、来源记录、后续接入路线
```

四个原项目保留独立历史与文件，本阶段没有向它们推送。来源版本和后续适配约束见 [来源基线](docs/source-baseline.json)；路线见 [后续阶段](docs/ROADMAP.md)。
